{\footnotesize
\textit{Device and models.} iPhone~15 Pro Max (\texttt{iPhone16,2}), iOS~27.2.1,
8~GB RAM; charging at 95\% battery; thermal state fair. Release build of revision
\texttt{7859f987c1c0} (no uncommitted tracked changes), compiled with the
headless benchmark entry point enabled. Classifier
30{,}820{,}096~B (SHA-256 \texttt{39e1b63dac8d\ldots}) and YOLO26n detector
9{,}768{,}796~B (\texttt{baa36404dbb6\ldots}), the same files as on the Xiaomi
device. The end-to-end paths used the same checksum-locked photographs as the
Xiaomi session.

\textit{Isolated-stage figures} (separate measured loops on synthetic patterns,
so they need not sum to the end-to-end means): classifier inference mean
23.07~ms; preprocess 1.83~ms; image decode 0.12~ms. Detector inference mean by
input resolution: $1920\times1080$, 51.32~ms; $1280\times960$, 53.31~ms;
$640\times480$, 54.75~ms; post-processing 0.16~ms and output transfer
0.25--0.27~ms. Within the end-to-end loop on accepted paths: preprocessing
5.26--6.18~ms, classifier 29.75--30.97~ms, detector 56.70--59.60~ms and
post-processing 0.17--0.20~ms.

\textit{Notes.} (1)~Process-level CPU utilisation was 1.81 (iOS
\texttt{getrusage}), which is not comparable with the Android per-thread
figure. (2)~Sub-millisecond model-initialisation readings are excluded because
the runtime loads model data lazily. (3)~Earlier sessions are archived in the evidence package but not reported:
three of 14 September 2026 (iOS~26.6.2, rejection path only, a build with
uncommitted changes) and one of 19 November 2026 (all paths, debug build of
revision \texttt{1ca6261b8df8}; accepted paths 148.19--172.16~ms, slower mainly
in unoptimised preprocessing).
